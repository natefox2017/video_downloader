# 视频混淆：原理与实现文档

对应模块：`src/obfuscate.py`（核心）+ `fission.py`（拼接 + 裂变）+
`ui/window.py` 的「混淆」开关。
逆向样本：某「去重」软件的输出文件（伪装成 `.mp4` 的受损 Matroska）。

---

## 一、一句话原理

**只换外壳，不动画面。** 把视频重编码一次后，装进一个「被故意写坏的 Matroska 容器」，
扩展名仍写成 `.mp4`：

- 本地播放器按规范严格解复用 → 读到被抹坏的字段 → 整个文件拒收（`Invalid data found`）；
- 平台服务端上传后会**先重做一遍转码/转封装**，解复用容错度高，直接读码流里
  SPS 的真实尺寸 → 正常出片。

画面数据从头到尾是同一坨：把容器修好（补回分辨率字段）就能无损还原播放。

## 二、容器的五处人为破坏

对样本的逆向结论（`process_video` / `_clone_container` 逐项复刻）：

| 位置 | 破坏方式 | 后果 |
|---|---|---|
| `Video` 的 `PixelWidth`/`PixelHeight` | 替换成同长度 `Void` | **致命**：解码器读不到分辨率，整个文件被判无效 |
| `Info` | 删 `TimestampScale` / `SegmentUID`；`MuxingApp`/`WritingApp` 的元素 ID 写错 +1（0x4D81/0x5742） | 结构指纹异常 |
| `SeekHead` | 首子元素 Void 顶掉 CRC；某条 SeekID 写成 `0x84ECECEC` | 索引失效 |
| `Cues` | 索引全部失效 | 无法 seek（但不影响顺序播放） |
| `Tags` | `DURATION` 写死假值 | 元数据不可信 |

**Void 与原字段等长**是关键设计：文件结构不位移，后面所有元素偏移原样保留。
最小修复 = 只把 12 字节的 `Void+Void+DisplayUnit` 换回 `PixelWidth+PixelHeight`（实测只改 10 字节即可播放）。

## 三、编码配方（从样本码流反推，参数级 1:1）

x264 会把**本次编码的完整参数表**写进第一帧的 SEI（user_data_unregistered），
dump 出来即得到对方"命令行"：

```
ref=3 deblock=1:1:0 analyse=0x3:0x113 me=hex subme=7 psy_rd=1.00,0.00 mixed_ref=0
me_range=16 trellis=0 8x8dct=1 chroma_qp_offset=-4 threads=4 lookahead_threads=4
sliced_threads=1 slices=4 interlaced=tff bframes=3 b_pyramid=2 weightb=1 open_gop=0
weightp=0 keyint=250 keyint_min=25 scenecut=40 rc_lookahead=10 rc=crf mbtree=1
crf=22.0 qcomp=0.60 aq=1:1.00
```

要点：**4 切片/帧 + 隔行 TFF 编码**（样本把逐行素材当隔行编，`field_order=tt`）
+ 每帧 1 个小 SEI + AAC-LC 44.1kHz 立体声 192kbps。输出强制 **720×1276 / 30fps / High L3.1**。

ffmpeg 侧的等价写法（`_encode_cmd`，5 个易踩的坑）：

| 目标参数 | ffmpeg 写法 | 原因 |
|---|---|---|
| `deblock=1:1:0` | `deblock=1\:0\:0` | ffmpeg 用 `:` 分隔 -x264-params，必须转义 |
| `analyse=0x3:0x113` | `partitions=i4x4,i8x8,p8x8,b8x8` | `analyse=all` 会多开 p4x4 |
| `chroma_qp_offset=-4` | `chroma-qp-offset=-2` | x264 在 subme≥7 时自动再减 2 |
| `mbtree=1` | 显式写 | `preset superfast` 自带 `--no-mbtree` |
| `interlaced=tff` | `-flags +ilme+ildct -top 1` 且放在 `-x264-params` 之前 | 顺序不对不生效 |

已知不可复现项：逐帧 SEI 的载荷字节（样本 0x42/0x32 两种，本实现全 0x32），
属 x264 core 164 vs 165 的 `pic_struct` 取值差异，参数表既然零差异就无需纠结。

## 四、输出效果与裂变随机化

只保留一种效果：逐字复刻样本（原去重软件的输出），共用一次重编码（见 `_encode_cmd`），
最后封装时把分辨率元数据抹成 Void。

| 效果 | 封装方式 | 结果 |
|---|---|---|
| 本地不可播放（平台可播） | `_clone_container()`：分辨率抹成 Void | 本地所有播放器拒收；上传平台后重转码可播（同样本效果） |

**裂变场景的随机化**（同一视频裂变 M 份，要求每份字节必不同）：片头/片尾每份独立随机
抽取（`fission.pick_segments`）。编码参数与元数据**不随机**——CRF 固定 22、元数据用
**真实时长 + 当前时间**（`_fake_meta`，对齐「能过查重的原版 clone」），因为之前试过
把元数据写死假值（Duration=1.032s 而实际视频 300s）会被平台当异常信号导致查重失败。
多份之间的字节差异由「片头/片尾随机抽取」保证；纯混淆（无片头片尾）裂变时，若片头片尾
都关且每份内容相同，字节差异需另加随机源（见 `fission.process_one_fission` 的注释）。

## 五、处理流程

```
片头（随机 N 个）+ 主体 + 片尾（随机 N 个）  —— 可选拼接（fission.concat_segments）
       ↓ 拼成标准 MP4 中间件
源视频 → ffmpeg 一次重编码（720x1276/30fps/隔行/4切片，mid.mkv）
       → 自写 EBML 容器（_clone_container，纯 Python 逐字节重建，含随机化）
       → 输出 <主体名>_NN.mp4
```

容器重建时同步处理：CRC-32 按 ffmpeg 约定以小端落盘（`struct.pack("<I", zlib.crc32(body))`）、
Segment size 固定 8 字节编码、Cues 的 CueClusterPosition 随头部长度整体平移。

## 六、GUI 入口

主界面「混淆」开关：勾上后把主体视频裂变成 M 份（M 可指定 1~99），每份独立随机混淆；
不开混淆则输出标准 MP4。片头/片尾拼接与混淆互相独立，可任意组合。

## 七、多算法扩展（算法1 / 算法2 / …）

`obfuscate.py` 第四节是**算法注册表**，把「混淆算法」抽象成可切换、可并行的对象。
当前只有算法 `260917`（按「通过查重实测的日期」命名，逐字复刻 22.mp4，默认）。
**算法按日期命名**：今天实测通过就叫 `260917`；以后快手算法更新、换新配方时按当天日期
再注册新算法（如 `260930`），旧算法保留不删，界面用 radio 单选切换。加新算法不碰已有算法，崩溃面隔离。

**命名约定（用户定，务必遵守）**：
- 算法名 = 6 位日期 `YYMMDD`（如 `260917`），对应「该算法通过查重实测的当天」。
- **每天只留一个最终版**：同一天若测了多套，只保留最终确认的那一个，不加后缀、不并留。
- 正常节奏最多一周一个新算法；真出现「同一天必须并存两个」的极端情况，届时再议。

**统一接口**（每个算法对象暴露三个钩子）：

| 钩子 | 签名 | 职责 |
|---|---|---|
| `name` | 字符串 | 算法唯一标识（界面下拉用） |
| `label` | 字符串 | 展示名 |
| `encode_cmd(ffmpeg, src, mid) -> list` | 重编码命令 | 先把源视频压成标准 MKV 中间件 `mid` |
| `rewrite(mid_bytes) -> bytes` | 容器改写 | 把中间件改成该算法的混淆容器 |
| `meta(duration_ms) -> (dur_ms, date_ns, dur_text)` | 元数据 | 返回该算法要落盘的元数据三元组 |

**加一个新算法的步骤**（以「算法2 = 轻量重编码」为例）：

1. 在 `obfuscate.py` 写一个 `_algo_xxx()` 函数，返回上面五个字段的 dict；
   可复用本文件已有的 `_parse`/`_serialize`/`_find`/`_crc_node` 等 EBML 基础工具。
2. 在 `ALGORITHMS = {a["name"]: a for a in [ ... ]}` 里注册一行。
3. `process_video(..., algorithm="xxx")` 即可切换；`get_algorithm(name)` 负责按名取、未知名回落默认。

**调用链**：`window.py`（界面）→ `fission.process_one_fission(..., algorithm=...)` →
`obfuscate.process_video(..., algorithm=...)`。`algorithm` 参数已全程透传，界面只需加一个下拉框传名字。

**拼接与混淆完全解耦**：拼接（`fission._seg_command`）负责先把片头+主体+片尾拼成一条
标准 MP4，混淆算法只吃「已拼好的视频」这一个输入，不感知拼接细节。两者互不影响。

## 八、风险与注意

1. **重编码 ≠ 过内容查重**：换容器/抹字段只改文件哈希和部分编码特征，内容指纹比对照样会命中。
   本工具针对的是**文件级哈希去重**（同一文件重复上传被拦），不是画面级内容查重。
2. 混淆后的文件**本地无法预览/剪辑**，封面与时长元数据不可信。
3. 不同平台容错度不同，抹坏关键字段有转码失败的风险；重要素材先留一份标准 MP4 底稿。
4. 产物**没有任何本地办法直接验证画面**——需要检查时先用普通视频工具确认源内容无误。
