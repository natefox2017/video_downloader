# video_frame_tool

短视频批处理工具（GUI）。把「搬运视频目录」里的视频逐条加工成成品：

> **每条成品 = 封面 + 前贴×N + 搬运 + 尾贴×N → 拼接 → 复刻22 混淆**

用于素材批量投放、规避平台的文件级与内容级查重。

- **零第三方依赖**：只用 Python 标准库 + 外部 `ffmpeg` / `ffprobe`
- Windows / macOS / Linux 通用，代码中不写死任何素材路径
- 界面用 tkinter，配置记在 `settings.json`，下次启动自动回填

## 主界面

### 模块一「拼接素材（每条成品独立随机抽取）」

- **前贴**（可开关）：从前贴文件夹随机抽 N 个视频拼在搬运前面，N 可指定（1~10）
- **尾贴**（可开关）：从尾贴文件夹随机抽 N 个视频拼在搬运后面，N 可指定（1~10）
- **封面**（可开关）：从封面文件夹随机取 1 张图片，**强制拉伸**到成品尺寸后替换拼接片的
  第 0 帧（时长/帧数不变，只是画面被换掉）

### 模块二「搬运视频（一个搬运出一条成品）」

- 选择**搬运视频文件夹** —— 里面是要实际搬运的素材
- **随机处理 N 个**（slider）：默认 = 文件夹里视频总数（= 全都处理）；拖到 N 就从目录里
  **随机抽 N 个**搬运，**一个搬运出一条成品**，所以 N 就是本次产出的条数

### 关键规则

- **搬运目录里有视频才启用「开始」按钮**，不允许空跑
- **执行顺序固定**：拼接 → 复刻22 混淆（没有分支）
- **开始 / 停止合并为一个按钮**（运行中显示「停止」）
- **同时处理**：并发数默认 = CPU 核数的一半（上限 8）
- **输出到**：按钮右侧显示输出路径；默认 `~/Desktop/out`，未选择时自动落这里，目录不存在自动新建
- 分辨率固定 **720×1276**（对齐参考样本 22.mp4），不随前贴/搬运/尾贴变化
- 命名 = 两位序号开头 + `_` + 搬运视频名（如 `01_x31.mp4`；序号全局递增，便于排序且保证不重名）
- 每条产物文件哈希互不相同
- 总产出 = min(搬运目录视频数, slider 值)

原理与实现的完整说明见 [`docs/技术原理.md`](docs/技术原理.md)（本项目唯一的原理文档）。

## 安装与运行

```bash
# 方式一：一键启动（推荐，免安装）
./run.sh        # macOS / Linux
run.bat         # Windows（双击即可，或命令行运行）

# 方式二：不安装，直接用模块跑
PYTHONPATH=src python3 -m src

# 方式三：装成命令（之后随处可用）
pip install -e .
video-frame-tool
```

`run.sh`（macOS/Linux）和 `run.bat`（Windows）都会自动把 `src` 挂到 `PYTHONPATH` 并做环境自检
（Python / tkinter / ffmpeg），缺什么直接给修复命令。

- **会自己挑解释器**：不是「PATH 里第一个 python3」就用。macOS 上 Homebrew 的 `python3` 常常没装 `python-tk`，
  脚本会逐个试 `import tkinter`，挑第一个能用的。
- 指定解释器（不再回退，缺 tkinter 直接报错）：`PYTHON=/path/to/python3 ./run.sh`；Windows 上设 `set VFT_PYTHON=C:\...\python.exe` 后运行
- 只看会用哪个解释器、跑什么命令（不启动界面）：`VFT_DRY_RUN=1 ./run.sh`

## 开发约定

- **回归检查**：`python3 tests/test_video_frame_tool.py`
  只用标准库与临时目录，不碰用户素材。
- **改滤镜链**必须跑像素级抽帧断言。
- **性能结论必须重复测量取中位数**，单轮计时会骗人。

## 实现要点

- **复刻22 混淆**（`obfuscate.py` 的 `fieldmix`，界面唯一算法）：上下场混合 ——
  偶行场铺一张静态强彩色色块图（每成品重新随机，只出 1 帧再 `loop` 复用），奇行场放原画面；
  **第 0 帧整帧保留原画**（平台用第一帧取封面）。写 BFF 场序 + 真隔行编码，
  容器 `FieldOrder` 仍伪装成 TFF。随后一次 x264 重编码 + 一次容器改写，
  把分辨率元数据抹成 Void → 本地播放器拒读、平台重转码后可播。
  原理、配方与实测数据见 [`docs/技术原理.md`](docs/技术原理.md)。
- **算法可扩展**：算法注册在 `ALGORITHMS` 表里，加新算法 = 新增一个算法对象 + 注册一行，
  不动已有算法。目前表里只有 `fieldmix` 一个。
- **拼接**（`fission.py`）：前贴 + 搬运 + 尾贴各段先重编码成固定 720×1276 / 30fps，
  再 concat demuxer 无损拼接；无音轨的段补静音轨。封面 = 强制拉伸到成品尺寸后叠在
  第一段的第 0 帧上（时长/帧数不变）。只有搬运、没开任何拼接项时跳过拼接，直接进混淆。
- **进度只吃真实数字**：编码来自 ffmpeg `-progress pipe:1` 的 `out_time`，
  `_run()` 边读 stdout 边回调，另有独立线程排空 stderr 防管道写满死锁。
- **进度条从开工第一秒就在爬**：总进度 =（已完成条数 + 各在跑条目的本条完成度）/ 总条数
  （`proc.blend_progress`）。每条成品内部还会把「拼接各段」与「复刻22 混淆」两块进度
  按权重合成一条 0~1 的本条完成度（`fission.CONCAT_WEIGHT`），所以不会出现
  「前面几十分钟不动、快结束才跳」；进度只增不减（并发上报在同一把锁里入队）。
- **进度区只报总进度**：进度条右边只显示百分比（不显示「已完成/总数」条数）；
  日志每条成品只报「第 N 条：开始处理 / 完成」，不再刷重编码、组成明细。
- **配置记忆**：用户上次选择的路径与参数记在 `settings.json`（位置见
  `platform_compat.py` 的 `user_config_dir`），下次启动自动回填。
