# video_frame_tool

短视频批处理工具（GUI）。把「搬运视频目录」里的视频逐条加工成成品：

> **每条成品 = 封面 + 前贴×N + 搬运 + 尾贴×N → 拼接 → 复刻22 混淆**

用于素材批量投放、规避平台的文件级与内容级查重。

- **零第三方依赖**：只用 Python 标准库 + 外部 `ffmpeg` / `ffprobe`
- Windows / macOS / Linux 通用，代码中不写死任何素材路径
- 界面用 tkinter，配置记在 `settings.json`，下次启动自动回填

## 主界面

### 模块一「拼接素材（每条成品独立随机抽取）」

- **前贴**（可开关）：从前贴文件夹随机抽 N 个视频拼在搬运前面，N 可指定（1~10）
- **尾贴**（可开关）：从尾贴文件夹随机抽 N 个视频拼在搬运后面，N 可指定（1~10）
- **封面**（可开关）：从封面文件夹随机取 1 张图片，**强制拉伸**到成品尺寸后替换拼接片的
  第 0 帧（时长/帧数不变，只是画面被换掉）

### 模块二「搬运视频（一个搬运出一条成品）」

- 选择**搬运视频文件夹** —— 里面是要实际搬运的素材
- **只处理前 N 个**（slider）：默认 = 文件夹里视频总数；拖到 N 就只处理排序后的前 N 个，
  **一个搬运出一条成品**，所以 N 就是本次产出的条数

### 关键规则

- **搬运目录里有视频才启用「开始」按钮**，不允许空跑
- **执行顺序固定**：拼接 → 复刻22 混淆（没有分支）
- **开始 / 停止合并为一个按钮**（运行中显示「停止」）
- **同时处理**：并发数默认 = CPU 核数的一半（上限 8）
- **输出到**：按钮右侧显示输出路径；默认 `~/Desktop/out`，未选择时自动落这里，目录不存在自动新建
- 分辨率固定 **720×1276**（对齐参考样本 22.mp4），不随前贴/搬运/尾贴变化
- 命名 = 搬运视频名 + `_` + 两位序号（全局递增的成品序号），便于排序且保证不重名
- 每条产物文件哈希互不相同
- 总产出 = min(搬运目录视频数, slider 值)

原理与实现的完整说明见 [`docs/混淆原理与流程.md`](docs/混淆原理与流程.md)，
以及项目根的 [`复刻22_已验证备份_20260919/README.md`](../复刻22_已验证备份_20260919/README.md)
（22.mp4 的逐场量化结论与实测数据）。

## 安装与运行

```bash
# 方式一：一键启动（推荐，免安装）
./run.sh        # macOS / Linux
run.bat         # Windows（双击即可，或命令行运行）

# 方式二：不安装，直接用模块跑
PYTHONPATH=src python3 -m src

# 方式三：装成命令（之后随处可用）
pip install -e .
video-frame-tool
```

`run.sh`（macOS/Linux）和 `run.bat`（Windows）都会自动把 `src` 挂到 `PYTHONPATH` 并做环境自检
（Python / tkinter / ffmpeg），缺什么直接给修复命令。

- **会自己挑解释器**：不是「PATH 里第一个 python3」就用。macOS 上 Homebrew 的 `python3` 常常没装 `python-tk`，
  脚本会逐个试 `import tkinter`，挑第一个能用的。
- 指定解释器（不再回退，缺 tkinter 直接报错）：`PYTHON=/path/to/python3 ./run.sh`；Windows 上设 `set VFT_PYTHON=C:\...\python.exe` 后运行
- 只看会用哪个解释器、跑什么命令（不启动界面）：`VFT_DRY_RUN=1 ./run.sh`

## 开发约定

- **回归检查**：`python3 tests/test_video_frame_tool.py`
  只用标准库与临时目录，不碰用户素材。
- **改滤镜链**必须跑像素级抽帧断言。
- **性能结论必须重复测量取中位数**，单轮计时会骗人。

## 实现要点

- **复刻22 混淆**（`obfuscate.py` 的 `fieldmix`，界面默认算法）：
  - 画面：偶行场铺一张**静态强彩色色块图**（每成品重新随机，只出 1 帧再 `loop` 复用，
    避免闪烁与码率暴涨），奇行场放原画面；**第 0 帧整帧保留原画**——平台用第一帧取封面，
    第 0 帧若是色块，成品封面就是彩虹横纹。
    写 BFF 场序 + 真隔行编码，容器 `FieldOrder` 仍伪装成 TFF（这个矛盾是样本的关键特征）。
  - 容器：一次 x264 重编码（配方逐项对齐样本 SEI）后，把分辨率元数据抹成 Void →
    本地播放器拒读、平台重转码后可播；Duration 写死 1032ms、Tags DURATION 写死 `00:00:01.121`。
  - 按「源帧数 − 1」截帧，复刻样本丢掉最后一帧的行为。
  - ⚠️ `blend` 的 `N` **从 1 起算**，判断「第 0 帧」必须写 `if(lt(N,1.5),A,B)`；
    写成 `lt(N,1)` 永远不生效。
- **算法可扩展**：算法注册在 `ALGORITHMS` 表里，按「通过查重实测的日期」命名。
  加新算法 = 新增一个算法对象 + 注册一行，不动已有算法。目前表里只有 `fieldmix` 一个。
- **拼接**（`fission.py`）：前贴 + 搬运 + 尾贴各段先重编码成固定 720×1276 / 30fps，
  再 concat demuxer 无损拼接；无音轨的段补静音轨。封面 = 强制拉伸到成品尺寸后叠在
  第一段的第 0 帧上（时长/帧数不变）。只有搬运、没开任何拼接项时跳过拼接，直接进混淆。
- **进度只吃真实数字**：编码来自 ffmpeg `-progress pipe:1` 的 `out_time`，
  `_run()` 边读 stdout 边回调，另有独立线程排空 stderr 防管道写满死锁。
  界面按「已完成条数 / 总条数」算百分比。
- **配置记忆**：用户上次选择的路径与参数记在 `settings.json`（位置见
  `platform_compat.py` 的 `user_config_dir`），下次启动自动回填。

### 已删除的功能（2026-09-19 按用户要求清理）

早先做过、后来下掉并**连同代码一起删除**的功能，历史实现见 git 历史或
[`复刻22_已验证备份_20260919/`](../复刻22_已验证备份_20260919/README.md)：

- **改音色**（原 `audio_fx.py`）：`asetrate` 抬高采样率 + `atempo` 拉回原时长，只变音色、
  时长不变，视频流 `-c:v copy`。实测对查重帮助有限——平台若按 ASR 文字比对，文案没变照样命中。
- **加噪点**（原 `obfuscate.noise_chain`）：编码滤镜链末尾追加 `noise=alls=N:allf=t+u`。
  体积代价大（真实素材中档 ≈ 高频 +44%、体积 +86%），且平台转码会把它抹掉。
- **旧算法 `260917` / 命令行脚本 `obfuscate_cli.py`**：只换外壳不动画面的那套配方。
  实测已被「复刻22」取代，代码在备份目录里（`obfuscate_cli.py`，三算法齐全）。

需要重新启用其中任何一个，从备份目录取代码接回去即可，不要凭记忆重写。
